# 小米 Alive 壁纸

主页入口位于「Vivo Alive 壁纸」下方。列表、预览、进度条和落地点控件来自小米主题应用的原版 DEX 与资源；宿主负责提供本地数据、系统状态和应用操作。未调用原版主题应用的初始化、账号或下载服务。

## 场景和离线使用

| 场景 | 原版渲染器 | 落地点 |
| --- | --- | --- |
| 月球 | Filament / MoonMrePlayer | 5 |
| 雪山 | Snow JNI | 1 |
| 几何 | Unity | 1 |
| 土星环 | Unity | 1 |
| 地球家园 | Filament / EarthMrePlayer | 5 |
| 红色火星 | Unity | 5 |

六款已内置，点击场景后在后台自动准备，无需下载或手动导入。以前缓存的有效原包或已安装的匹配版本仍可复用。版本和 SHA-256 固定在 `app/assets/xiaomi/catalog.json`；缓存损坏时从内置资源重新还原，临时文件通过完整校验后才替换目标文件。

六个原版场景包共 434,688,109 字节（414.6 MiB）。沿大 ZIP 条目边界分块，相同内容只存一份，再使用 XZ 无损压缩，521 个共享块共 330,241,580 字节（314.9 MiB）。首用按需还原所选原包，完整 SHA-256 与原包相同，未删除纹理、落地点、代码、ABI 或时间变化分支。原版 UI 包约 27.6 MiB，复用已有的澎湃时钟资产。各场景使用独立进程和原包摘要对应的原生库目录，避免同名 Unity 库互相覆盖。

还原流程在后台执行，使用跨进程文件锁和只读临时文件；每块验证长度与摘要，最终验证原 APK 摘要后原子提交。XZ 解码器来自固定版本的 Java 源码，限制解码内存为 32 MiB。准备完成后直接复用磁盘文件，渲染期间不解压，未使用的场景不提前展开。

0.4.23-preview 的完整安装包约 570.4 MiB。主力 ColorOS 设备用独立空目录完成 46 项检查，覆盖六款逐字节还原、缓存复用、错误回滚、损坏修复和并发准备；原有 198 项时钟与资源检查同时通过。首次准备月球约 2.4 秒、雪山 1.8 秒、几何 3.4 秒、土星环 4.3 秒、地球 3.1 秒、火星 18.8 秒。这些是单次设备测量，非性能保证。超过 300 ms 的准备过程显示等待提示；返回取消只停止自动打开预览，已开始的缓存准备会在后台完成。

同日主力机实际列表进入月球预览已截图确认。火星另将原缓存临时移开，从列表点击后出现准备提示，自动从内置数据还原并进入原版动态预览；新文件摘要与原包一致，验证后移除了临时备份。未应用或更改用户当前壁纸。最终安装包与本地 SHA-256 一致，测试专用包及临时解压目录已清理。

## 状态和应用

- 原版 AOD、锁屏和桌面动画由现有 ColorOS SystemUI 状态通道驱动；普通系统使用壁纸指令、屏幕和锁定状态作为后备。
- 壁纸不可见或显示器关闭时暂停原版渲染器，重新可见时恢复。
- 系统页面位置 `0..1` 转为原版 `Offset_0..100`，每个变化样本按原服务延后 100 ms 交给渲染器，不丢弃中间轨迹。总幅度固定，按实际桌面页数分配，不额外放大单页幅度。
- Unity 渲染线程的消息队列就绪后才绑定表面和恢复运行，再等待原版 `InitFinish` 回调。避免冷启动时丢失恢复消息造成黑屏。
- 应用时保存落地点。Root 路径只允许本应用的六个壁纸组件，并核对锁屏、桌面设置结果；未取得 Root 时使用系统动态壁纸确认页。取消系统确认会恢复原落地点。
- AOD 预览优先读取小米原版快照接口；不存在时，用已有的原版 MIUI AOD 渲染器生成预览，不绘制仿制时钟。
- 实际 AOD 复用原版 SuperWallpaperClock，沿用留光的时钟隐藏、通知避让和恢复通道。实际锁屏继续使用 ColorOS 时钟。小米不使用留光的照片展开帧确认条件。
- AOD 唤醒的锁屏候选指令沿用小米 100 ms 等待窗口；窗口内认证解锁会取消候选，避免先向锁屏镜头移动再改去桌面。
- 首页三个小预览使用原包的 `aod_small_preview`、`lockscreen_small_preview`、`home_small_preview_N` 和深色版本，桌面图跟随保存的落地点。它们是原版静态缩略图，不启动三个额外原生渲染器；点击进入对应阶段的实时预览。AOD 小时钟按当前时间更新，退出首页停止更新。

## 同场景变化

- 月球原版保留 15 组锁屏镜头/光照配置、随机卫星和轨道动画。实际壁纸调用原版纯函数计算月相并发送 `Phrase_`；预览遵循原包，不注入实际服务专属的月相指令。
- 地球原版根据本地时刻计算太阳和昼夜，五个落地点的日夜素材完整保留。
- 雪山原包 `CameraCtrl.lua` 使用 `os.time` / `os.date`，将本地一天分成 9 个时段，映射纹理、光照和云层；保持原版自动更新时间及渐变，不用系统深色开关替代时段。
- 火星、土星环、几何完整加载原始 Unity 数据和原生库，未裁掉场景分支。其内部镜头组合尚未逐个穷举，不能仅凭落地点数量断言全部变体数量。

### 后续实机核对

- ColorOS 主力机真实桌面雪山服务收到 `50 / 60 / 70 / 80`；步长 `0.1`，对应 11 页。备用机原版雪山真实翻页收到 `0 / 50 / 100`，对应 3 页。
- 澎湃桌面 `libapp.so` 的 `.gnu_debugdata` 保留 Dart 函数符号。ARM64 核对 `WorkspaceGetxController._updateWallpaperOffset` 为 `page / (screenCount - 1)`；原服务将其转换为 `Offset_0..100`。两机单页幅度差异来自页数。用户确认保留原算法。
- 152 项签名 APK 实机检查通过：包括六款原版时钟挂载/绘制/恢复、所有场景与落地点的日夜缩略图资源、三个入口阶段，以及留光时钟独立性。此测试不代替真实 ColorOS SystemUI AOD 和指纹认证验收。
- 备用机临时应用 OpenAlive 雪山后，首页三个小预览及分别进入 AOD/锁屏/桌面阶段已截图检查。应用界面遮挡壁纸时服务 `running=false`，返回桌面恢复 `running=true`。测试结束恢复了备用机原来的小米官方雪山服务。

### 切换与 AOD 尺寸修正

- 魅族编辑器按 `CleanWallpaper` 具体组件判断是否需要系统应用流程，避免把同包的小米服务误认作已应用。主力机确认取消时保留原配置和雪山服务；随后系统已切换到 `CleanWallpaper`。
- 超级壁纸 AOD 时钟补上原 MIUIX 密度计算，仅作用于它自己的资源上下文，保留原窗口 dp 限定。主力机计算值为 586 dpi，宿主仍为 640 dpi；157 项检查通过，包括其他澎湃时钟密度与尺寸不变、六款时钟挂载和恢复。SystemUI 中最终大小需重启加载后验收。
- 地球、月球 Filament 版本未处理通用 `ForceAOD`，恢复状态时改发它们原生的 `ForceStaticAOD_1`。没有修改原模型、投影或统一缩小场景。主力机实际月球 AOD 主体宽度约为屏宽 60%，与原版参考一致；雪山实际 AOD 画面已检查。
- 五款魅族气泡壁纸保留原 RGB 混合和动画逻辑，仅将最终输出 alpha 保持不透明，避免窗口合成透出下层。修复前五款输出存在半透明像素；修复后设备 GPU 的亮/暗、三阶段共 90 帧 RGBA 读取均为 alpha 255。用户确认回桌面泛白恢复正常。

### 2026-09-29 AOD 时钟淡入淡出

- 对照原 `MIUIAod.apk` 的 `DozeHost.startEnterAnim`：普通超级壁纸时钟容器使用 1000 ms 的 `AccelerateInterpolator` 淡入，样式默认延迟为 0。原版锁屏另有 500 ms 的时钟动画，其 JADX 缺失的睡眠调用点已用 baksmali 核对，但本实现不接管 ColorOS 锁屏时钟动画。
- 只对独立 AOD 时钟施加淡入淡出。AOD 淡入同时乘上原生显示窗口的透明度；完全黑屏时取消进入动画，单击重新显示 AOD 时重新淡入，不增加显示请求、唤醒锁或定时唤醒。
- 唤醒至锁屏时，独立 AOD 时钟以 500 ms 淡出；锁屏时钟立即交回 ColorOS，恢复新增动画之前的处理路径。**AOD 退出 500 ms 是适配选择**，不能视为已经确认的原版 AOD 退出参数。小米超时转黑与 ColorOS 的屏幕窗口控制不同，仍由 ColorOS 负责结束显示。
- 重复的时间刷新不重启动画；快速亮灭屏时，AOD 从当前透明度反向过渡。保留原有 AOD 时钟隐藏以及直接解锁时直到 keyguardGone 才释放遮罩的逻辑。留光原有的提交帧确认与 167 ms 恢复动画不变。
- 原版预览页继续运行其自身场景动画，没有替换预览页的 200 / 250 / 300 ms 参数。实际锁屏仍用用户选定的 ColorOS 时钟。
- `tests/android/XiaomiFidelityTest.java` 在主力机通过 198 项检查，覆盖原有六款时钟和资源，以及 AOD 透明度、中断、重复刷新、黑屏后唤醒、认证解锁、资源清理及留光独立性。新增检查确认进入 AOD 不创建锁屏淡出动画、返回锁屏立即释放原时钟、AOD 淡出中原时钟透明度不变。新版 APK 已安装并核对哈希；独立窗口测试不代替 SystemUI 实际锁屏验收，后者需要重启加载新模块。

### 设备动作与方向权限

- 主力机已通过 Root 将本包的 `DIRECTION_SENSORS` 操作设为 `allow`，并读回核实。授权前读到 `default` 和近期拒绝记录；这只能说明系统曾限制此操作，尚不能证明它就是偶发光栅失效或额外耗电的全部原因。
- 新的 Root 平台适配器按 ROM 的 `android:direction_sensors` 名称查询操作编号，为主用户 `org.aliveclean` 授权后再次检查。成功应用 AOD 时顺带执行；也支持独立 `motion-permission` 命令。不修改其他应用权限，不循环重写系统设置。没有该操作的系统返回不支持，不影响壁纸应用结果。
- 新版 APK 的 `motion-permission` 适配器已在主力机连续执行两次，均返回 `motionAllowed=true`，随后系统读回 `DIRECTION_SENSORS: allow`，确认重复调用也有效。
- 本次保存的电源和进程日志没有确定数秒亮屏卡顿的原因。按用户要求不再反复尝试复现，没有据此修改原版渲染器暂停逻辑。
